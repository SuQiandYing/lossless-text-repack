## 身份与投影

解析源得到内存 IR，直接从 IR 分别生成文本和 ASM。二者是平级投影，互不作为对方的发现数据源；ASM 没有导出时仍应可以提取与回封文本。

机器身份用 `(src_id, object_id)`，共享存储另用 `storage_id`。`idx` 是源内展示序号，不是跨源主键；旧物理偏移是来源证据，不是重排后的身份。`src_id` 应由清单绑定相对路径和源哈希；两个相同字节但不同路径的源不能因哈希相同而被无意合并。

`object_id` 在同一个固定基线的重复解析/渲染中稳定。优先使用格式原生 ID，或源身份加结构路径和明确消歧序号；不得用文本内容作为身份。重建后通过记录的 ID 映射追踪变化，不能假定旧偏移不变。新结构对象需显式 `new:<namespace>:<id>`，不得凭行号或新偏移猜测。

合库可减少机器侧 I/O；文本和 ASM 默认镜像源相对目录，避免同名覆盖及跨源 idx 冲突。清单明确映射源、投影、分片、哈希、编码与协议版本。合库是适合批量的布局，不要求简单单文件任务创建无用途的持久 IR。

## 四编码与无损字符

| 字段 | 职责 |
|---|---|
| `source_encoding` | 原始字节解码为文本 |
| `target_encoding` | 译文编码为目标字节，长度/可表示性按此计算 |
| `text_encoding` | 双行文件自身编码；推荐显式 UTF-8，是否 BOM 由协议固定 |
| `asm_encoding` | ASM 投影文件自身编码 |

四者不能互相推断。默认取方言/项目声明；无证据时不能普遍默认 CP932。编码选择写入作业清单和投影头，导入时校验兼容性。目标编码变化是显式配置变更，需重新编码校验和策略 probe，不能由编辑文件中一处头字段悄悄改变。

解析错误不能静默 `replace` 或 `ignore`。`surrogateescape` **可以**在同 codec 和相同错误处理链路下无损往返，并非必然有损；但孤立代理字符跨 JSON、GUI、不同 codec 或第三方编辑器时有兼容风险。默认对不可安全显示的原字节保存 raw span、哈希和占位符，并冻结未经证明可编辑的条目。若内部使用 `surrogateescape`，测试整个输入—序列化—输出链，且不把不可显示字符直接交给译者。

Unicode 规范化、智能引号、行尾空格修剪均可能改变语义，不默认执行。原文展示、导入锚和编码验证使用协议规定的精确字符串，而不是 `strip()` 后比较。确实需要归一化时作为显式转换记录，并与零编辑保真约定分开。

## 占位符和字面歧义

普通反斜杠是普通文本：`\x41` 不是字节 `41`，不隐式执行 Python/JSON 反转义。显示不安全的原字节可用大写 token：

```text
{{00}}       一个字节
{{FF:01}}    两个字节
```

每条 IR 保存 token 序列、各 token 原字节/位置/语义，以及 `ph_count / ph_bytes / ph_hash / ph_policy`。默认保护 token 顺序与值；某格式允许移动时由明确的 `ph_policy` 定义允许的变换。仅比较多重集合不能保护“同值但位置/用途不同”的控制码。

### 原文本身包含 `{{00}}` 怎么办

不能用一条全局正则把所有看似 token 的文本都展开。适配器必须选定并版本化一种可逆机制：

1. **token 台账模式**：投影携带/关联 token 身份，解析器区分已登记控制 token 与普通文本；插入的新 token 需显式操作，不能自动当原字节。
2. **保留前缀模式**：定义字面 `{` 的可逆转义，例如协议声明 `{{LBRACE}}` 表示一个普通 `{`；先把原文本的所有 `{` 编码，再插入字节 token。导入通过单遍词法器还原，禁止递归二次展开。原文的字面 `{{LBRACE}}` 因括号先被编码也不会碰撞。

已有 TEXT/2 若没有该机制，遇到字面 token 歧义应明确拒绝编辑/标为待解决，不能靠猜测放行。不得无版本地改变旧文件含义；格式扩展需新版本或明确能力标记及迁移器。

若选保留前缀模式，示例：原始六字符 `{{00}}` 可投影为 `{{LBRACE}}{{LBRACE}}00}}`，导入后仍是六字符，不变为 NUL。普通反斜杠、斜杠和全角空格保持可读。占位符替换只处理其语法域，字符串引号的转义属于 ASM 外层语法，二者不能混用。

终止符必须恰好由一处负责：若字符串 token 中包含终止符，编码器不得再附加；若终止符是字段结构，则文本内容不包含它，编码器按格式附加。私用区字符是否以原字节展示取决于字体/协议；不能笼统断言所有私用区都是无效字符。

## 双行格式与分片

兼容 TEXT/2 的基本形状示例（字段取决于实际版本）：

```text
# TEXT/2 ir=1 tool=1 src_sha256=SOURCE_SHA256
# encoding source=cp932 target=cp932 file=utf-8
# scope kind=all range=ALL part=1/1
# tags name msg choice label ui system ruby misc
# idx=00000001 off=0x00000010 tag=msg speaker=NAME
○00000001○msg○原文
●00000001●msg●原文

```

译文预填原文；`target == source` 表示无修改，不判定其主观翻译进度。空译文默认拒绝；若源本身合法为空，应保持零编辑可导入，格式确实支持删除/空串翻译时通过显式操作表示，不能把误删当作未翻译。

本包 `check_dsat.py` 的现成读入契约见 [验证协议](validation.md)：TEXT/1 与 TEXT/2，
四行头、八位 idx、固定 tag 集。不要为普通提取任务随意发明不兼容版本。
说话人信息不参与正文身份：机器绑定保留在 IR 的 `NameBinding`/源结构路径，
没有说话人时省略 `speaker` 注释，不伪造一个名为 `null` 的人名条目。
说话人是真实、可独立编辑的存储字段时导出独立 `tag=name` 条目；
仅为动态显示或推导标签时只作上下文说明，不冒称可回封人名。
含空格或特殊标点的名字可在单独的人读注释中完整展示；不要扩展机器元数据的词法而不更新解析器。
复杂 token 扩展才需要新版本；普通样本优先使用现成语法。

条目间留空行改善阅读，解析器可忽略结构空行，但不能去掉文本行末尾的有效空格。idx 固定宽度十进制；三行 idx 一致，行分隔符严格对应；内容按行剩余部分解析，不能因文本中出现 `○`/`●` 再随意分割。多行原文要有显式换行 token/长度化机制，不能让一条正文变成新记录。

### 导入信任边界

从当前源重新解析得到权威 IR，再校验：

1. 清单中的源身份/哈希、协议与方言/工具兼容版本匹配。
2. 文件声明与实际来源、预期分片范围一致；无法唯一绑定源时拒绝。
3. idx 在该源唯一且存在；注释、原文行、译文行的 idx/tag 彼此一致，且 **tag 与 IR 一致**。
4. 原文逐字符等于 IR 的同版本渲染结果；有 `off/object_id` 等字段时也核对。
5. 策略取 IR；投影中 `policy` 若存在仅用于核对，不得覆盖 `frozen/length-locked` 等限制。
6. 冻结条目不得修改；待审条目若修改，须具有适配器支持且可验证的审阅记录。
7. 占位符语法、身份、顺序/允许变换、终止符正确；目标编码严格可表示。
8. 编码后长度进入策略 probe；投影输入通过不代表布局可行。

元数据只保留机器校验需要或译者能用来做决定的内容，例如说话者、上下文范围。共享存储若意味着修改影响多处，应在首次说明/可查询引用列表中清楚呈现，不必为每行重复长段机制解释。已冻结但可见的条目应可审阅；不通过隐藏条目消除疑问。

### 完整性是条目集合，不是分片编号齐全

完整导入需验证每个源所有片的条目集合：

```text
each(part_i.ids) has no duplicates
intersection(part_i.ids, part_j.ids) == empty for i != j
union(all_parts.ids) == manifest.expected_ids
```

“part=1/2 和 part=2/2 都出现”并不能发现两片都含 idx=1 却遗漏 idx=2。缺片、跨片重复、越界 idx、跨源同号都必须有反例测试。分片顺序可变化，但源和集合不能漂移。

部分导入仅在用户明确选择范围且协议支持时成立：期望集合来自已验证清单/调用参数，不由编辑文件自己缩小以逃过遗漏检查。范围外对象保持原样，报告 `partial` 范围；不能宣称全量导入。

为兼容旧格式保留经过测试的只读/导入路径；版本不同但缺乏迁移证明时给出迁移指导，不盲目将所有字段改为可选。陌生字段不能被解释为放宽策略。

## 受限 ASM 编辑

ASM 是结构化审计视图，可以提供受限编辑能力，但不是任意文本改动都可回封。确定性 diff 只告诉我们哪里变了，不能替代语法、对象身份、引用与语义校验。

每个可编辑记录携带稳定 `object_id`；字符串带 `storage_id/sid`；偏移作为只读注释。指令目标用标签/对象 ID，声明相对基准（指令起始、末尾、PC 或层基址）与地址空间。T1/T2 数据渲染为 cell/字段，不伪装成指令；未知块可以为只读 opaque 引用，原字节由 IR/源保留，不要求把整块十六进制塞进可编辑视图。

### 适配器应声明的语法子集

以下是契约示例，非现有检查脚本自动提供的汇编器：

```text
.string id=S17 sid=STORE9 value="可读文本"
.field id=F4 type=u32 value=12
.instruction id=I7 opcode=JUMP target=L3
.label id=L3 target=I9
```

- 用明确定义的词法器解析引号、空格、注释与占位符。若 `value` 使用 JSON 字符串语法，只在该外层解析一次 JSON 转义；反斜杠在解码后的文本层仍是字面字符。
- 建立字段白名单及类型/范围校验，不允许修改 ID、原始哈希或策略字段来绕过定位。
- 默认支持已有对象的有限字段替换。未知指令、未声明的伪指令、行增删或重排若未实现则拒绝，不能忽略。
- 若实现插入/删除，显式提供 `insert-before / delete / retarget` 等操作及新 ID 分配、入站引用处置、共享存储克隆语义。不得从“删了一行”自动推断应该删除所有共享对象。
- 指令增删/控制流改变要求相关闭包语义满足能力矩阵；纯数据重排按自身结构证明，不能仅凭 ASM 语法形似指令要求全文件 T4。

保留非最小整数宽度、不可达槽位和共享子树的原始形态。明确区分“改共享存储，影响全部引用”和“复制存储并重定向一个引用”；后者需要额外能力，不能把同一 sid 的两个不同译文静默选一个。

## 双编辑面合并

```text
重新解析固定源 → 新鲜投影 → 各自解析已声明编辑 → 规范化 ChangeSet
  → 按 (src_id, object_id, field) 合并 → 共享/引用冲突检查 → 策略 probe
```

缺失的可选投影表示未使用，不表示删除其全部对象。哈希与新鲜投影相同的文件可跳过编辑解析，但仍验证源身份及本次必需门禁。缓存键包含所有渲染参数，不能只凭文件名跳过。

| 两面状态 | 结果 |
|---|---|
| 都未编辑 | identity |
| 只有一面编辑 | 校验并应用其 ChangeSet |
| 同对象同字段改为同一规范化值 | 合并为一次编辑，保留两个来源 |
| 同对象同字段改为不同值 | 冲突，显示双方值/文件/行，不提交 |
| 不同对象却共享存储，要求不兼容结果 | 共享冲突；除非显式支持克隆并重新绑定，否则拒绝 |
| 删除对象与另一面编辑/引用它 | 依赖冲突，不由先后顺序消解 |

规范化比较只能使用协议定义的等价性；不能通过 trim、Unicode 归一化等“清洗”掩盖真实差异。合并后进入 [重建与事务](rebuilding.md)，而不是按文件顺序各写一遍导致后一面覆盖前一面。
