## 按请求选择交付范围

| 请求 | 合理交付 |
|---|---|
| 观察/格式研究 | 证据、区域/形态与能力边界；不强制生成全部工具 |
| 导出文本 | 可复现入口、文本/清单、导出验证与明确回封支持情况 |
| 修改并回封 | 修改副本、可追溯计划、验证、回滚方式 |
| 面向译者的可用工具 | 完整四模块职责、三种入口、使用说明、默认两按钮 GUI、实际支持样本范围 |
| 性能优化 | 原始基准、热点、改动、输出等价验证和新测量 |

默认保留原版四个 Python 文件的入口职责；既有项目可映射到已有模块，但不能省去相应功能。
核心职责分离为方言、解析/IR、投影、规划/序列化、验证和入口。声明式参数带证据，
结构算法不散布难追踪魔数，但不是机械禁止任何十六进制字面量或条件分支。

面向使用者的说明按操作顺序：支持范围与版本、依赖、输入/输出、可复制命令、双行编辑例子、回封位置、真实错误码与处置、已知限制。说明只承诺实现且验证过的入口；没有 GUI 就不要列“双击 GUI”。维护者证据说明与使用说明分工不同，纯数据格式可叫格式分析而不是 VM 分析。

输出目录显式可配置，默认位于源之外且镜像相对路径，不覆盖源；使用固定清单绑定输入，不能递归把上一轮 `output/` 当新输入。对于多目录输入，记录相对根或源命名空间，避免同名文件覆盖。README 中说明用户拿到的哪一层文件可供目标程序读取，不能只说“成功生成”。

## 两按钮 GUI

完整工具默认保留以下两个主动作，布局与具体交互按完整 §11 实现，不另作自由简化：

1. **输出文本**：选择源/输出目录；默认导出双行文本，可勾选结构视图；可选产物缺失不能阻断文本主路径。
2. **回封文本**：绑定同一源清单，读实际存在的编辑面，展示变更与冲突，然后提交新输出。

CLI 保留可组合的阶段入口并与 GUI 调用同一核心函数。GUI 只管路径、参数、作业调度和展示，不另外实现解析/验证。零编辑检查、冻结策略、probe 不适用结果不能由 GUI 复选框关闭。

### 交互与预览

- 按当前已证明能力启用动作；源未通过必要基线检查时提示具体原因，不笼统显示“该游戏不能用”。
- 显示将处理的源数、编辑条目数、编码、策略、冲突/阻断、最终路径；字节增量若只是估计要标注。
- 冲突提供对象 ID/idx、双方值与位置；不提供一个默默覆盖的“继续”按钮。
- 输出同名已存在时明确覆盖/新版本规则，默认不覆盖未识别产物。
- 当前任务已授权批量运行可直接按所选范围完成，不强制人为点每个内部阶段。
- “无改动”是有效状态，应显示零编辑结果，不诱导用户制造无意义修改。

源与目标编码选项来自方言/项目默认，不通用假定 CP932。选择记录在清单，回封复用并校验。编码失败指出条目、字符和编码；可给经实际可表示性检查的候选，但“某 codec 能编码”不代表引擎支持它，不能自动换编码。

### Unicode 路径

Windows 拖放使用 Unicode API；ANSI 通道可能在程序收到路径前将不可表示字符替换，之后再解码不能恢复。GUI 框架及依赖要按实际环境检测，缺拖放依赖可降级为选择文件，不影响基本启动。

路径含 U+FFFD **不一定非法或损坏**，Windows 可以存在该字符。先保留原始 Unicode 路径，核对真实路径、收到的 API 类型与来源；若有替换证据，报告拖放链路损坏并建议选择文件。`?` 在普通 Windows 文件名组件中受限，但也不能对含设备前缀的完整路径做无上下文字符封杀。

回归测试用真实存在的含 `・`、中文、空格及允许的 U+FFFD 路径，验证逐字符传递与正确输出；既要覆盖损坏通道，也不能误拒绝合法路径。不要用“文件不存在”代替已知编码损坏的具体诊断。

### 长任务和取消

UI 线程不做大文件解析或同步等待。工作线程/进程取决于核心代码是否受 GIL、I/O 和外部库释放 GIL 的情况，不凭“Python 就只能多进程”定论。进度给完成文件/字节和当前阶段，无法可靠估算的剩余时间不编造。

取消关闭句柄并停止未提交工作，保留日志/checkpoint；清理仅限本任务 staging。独立文件允许部分成功，有跨源依赖则按事务组处理。失败后动作回到可重试状态，显示简短处置和可复制诊断信息。

详情区域可显示源哈希、区域 tier、实际能力、字节覆盖、零编辑结果、文本/标签证据分布、策略裁决、报告路径；不要把内部参数全部堆成让使用者猜测的选项。

### GUI 验收重点

- 单文件/目录、Unicode 路径、缺可选依赖、输出冲突、取消恢复。
- 仅 texts、仅 ASM（如实现）、两者同出与分次输出具有等价结果。
- 原文/冻结条目修改被拒、双面冲突可见、部分翻译可回封。
- 比原文更长但在容量内、超过容量可重定位、证据不足无法重定位三种情况分别验证。
- 最终内容与引用正确，不用文件长度必须变化作为 GUI 成功条件。
- GUI 与 CLI 对同一有效配置产生相同语义/字节结果，报告运行 ID/时间等易变字段另行比较。

## 批量与可恢复作业

批次共享只读方言、编码配置和编译规则；单源入口与批量入口复用核心。跨源引用在统一身份空间内建立，不因每个文件各自“成功”而漏掉关系。机器侧可合库，文本侧按源镜像；单文件不必为了模板构建空目录树。

清单至少记录：源身份/路径/哈希、配置与工具版本、投影路径、状态、证书/输出哈希。作业状态区分 `pending / running / passed / failed / cancelled / not_verified`，不要将“未执行”写成通过。

checkpoint 保存最后已提交步骤、下一可执行动作、输入身份与未完成事务。续跑复用已验证结果，但每次先校验缓存身份；源、方言、选项或相关依赖变化时只使相应闭包失效。临时 IR 验证快照见 [解析契约](parsing-evidence.md#对象图与封装层)，默认不交付全库 IR 不妨碍门禁执行。

并行结果由单写入者或独立分片聚合，不竞争同一 JSONL 文件句柄。以稳定 `src_id/object_id` 排序规范化结果；运行 ID/耗时放事件记录，不进入要求可复现的语义哈希。恢复过程保留失败事件，不覆盖成“第一次就通过”。

## 真实性能边界

### 先测量，再删重复工作

用代表性小/中/大样本及批量输入记录总时间、各阶段时间、峰值 RSS、源字节数、对象数与输出大小；注明硬件、Python/依赖版本、冷/热缓存、并发数。没有环境与基准，不给“快 100 倍”等普遍承诺。

用 `cProfile/pstats`、`perf_counter()`、启动导入分析定位热点。优先去掉真正重复的解析、渲染和探针读入，但证明删掉的检查没有独立覆盖：相同函数在状态/缓存/副作用不同情况下未必等价。一次确定性往返成功后的相同输入重复解析可不是必要的每文件门禁；独立进程、不同顺序或缓存设置的确定性测试仍能揭示状态泄漏，不能全删。

### 缓存与预计算

把稳定的 `struct.Struct`、codec 查找、掩码、规则和目标键集合移出热循环。跨源复用只读对象，不复用可变“当前源”状态。缓存键包括源哈希、工具/方言/协议版本、编码和相关选项；完整键校验前不使用跨作业解析缓存。

`set/dict` 可以加速引用候选筛选，候选仍须通过字段/边界/上下文证据验证；哈希 join 不是值相等即引用。某层全部 words 物化为 set 会增加内存，必要时分块或索引化处理。

### I/O 与内存

几 MB 文件一次读取通常简单有效；大文件可用 mmap/分块，但**mmap 不自动让整个算法成为 O(block_size) 内存**：IR、索引、数组、解压结果仍可能 O(N)。对随机引用、跨块字符串及压缩块明确持有的数据和上界，报告真实峰值。

顺序缓冲写比逐记录 open/flush 更合适；无需为了“一次写”将数 GB JSONL 先 `join` 成巨型字符串。可以按批写入，保证确定性顺序及必要的刷新/提交点。内容寻址 blob 可去重，仍验证引用计数与哈希；去重不能丢失不同对象身份。

`memoryview` 切片可避免复制；注意底层 buffer 生命周期和 mmap 关闭时仍存在的视图。记录用 slots、紧凑 tuple 或平行数组是否划算取决于数量与访问模式，先测量，不以某次对象大小结果作为跨版本定理。

### 批量数值解码

定长单元已被证明时可使用 `array` / `struct.iter_unpack` 等。`array('I')` 的 itemsize 是平台属性，不能不检查就当作精确 32 位；对齐、宽度和目标字节序必须验证。

```python
import array, struct, sys

if len(data) % 4:
    raise ValueError("CELL_ALIGNMENT")
words = array.array("I")
if words.itemsize == 4:
    words.frombytes(data)
    if sys.byteorder != target_endianness:
        words.byteswap()
else:
    fmt = "<I" if target_endianness == "little" else ">I"
    words = [value for (value,) in struct.iter_unpack(fmt, data)]
```

`memoryview.cast('I')` 按宿主原生解释且没有 `byteswap()`；仅在宽度/字节序已断言相同时可使用。所有优化仍须与明确字节序的参考实现比较，包括边界、不整除输入和大端/小端构造用例。

### 并发选择

纯 Python CPU 密集解析可评估进程池；释放 GIL 的压缩库或 I/O 密集阶段可评估线程。小任务的启动、pickle 与 IPC 成本可能使并行更慢，不写固定“少于 8 文件一律单进程”之类普遍规则。

worker 接收小而可序列化的参数，避免重复传巨大 buffer；输出可使用独立临时分片再归并，控制峰值内存。Windows 进程入口遵循可安全 spawn 的设计，避免 worker 导入时再次启动 GUI/进程池。并发数按实际内存/CPU/磁盘压力调节，而非默认开满。

可选快 JSON 库必须实测整数、浮点、Unicode、键排序与标准库的契约差异。没有依赖时正确运行；是否逐字节相同取决于公开序列化协议，若协议改变则版本化，不把“更快”当作输出格式漂移的理由。

## 性能验收

对优化前后的固定语料执行同一操作和配置：

- 零编辑输出与源逐字节一致；有编辑用同一 ChangeSet 证明目标结果与未编辑内容不变。
- 语义 IR、身份、站点、形态与标签分布相同，预期差异另列；确定性公开产物字节相同。
- 单源/批量、单进程/并行、可选加速依赖有/无具有相同结果。
- 覆盖、引用、占位符、分片及负例门禁仍实际运行；不能用“不报错”当作执行证明。
- 报告中同时列耗时与内存，不承诺某批次一定比单独运行快；未改善或退化如实记录。
- 缓存命中/失效、取消/重试和失败路径有测试，性能收益不能依赖读取陈旧结果。

性能改动不得取消源哈希绑定、完整覆盖、必需零编辑基线或编辑结果验证。验收脚本的真实覆盖和局限见 [验证契约](validation.md)，不把 skill 自测通过等同于某款游戏已经可运行。
