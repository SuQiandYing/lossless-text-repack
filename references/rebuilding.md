## 策略能力

| 策略 | 适用变化 | 必要证明 |
|---|---|---|
| `identity` | 无编辑 | 所有原字节/存储块可重放，T0 即可 |
| `in_place` | 新字节能放入已证明可写槽位 | 起止、容量、终止符、填充规则、共享关系 |
| `pointer-rewrite` | 将文本放到允许的新位置并更新引用 | 全部入站引用、地址基准/宽度、目标存储空间、外层依赖 |
| `full-layout` | 数据区/容器/代码相关布局变化 | 受影响闭包内布局、引用、计数、校验、变换全部可解 |

`pointer-rewrite` 不是“文本可以无限变长”：长度字段、指针宽度、引擎上限、归档空间、内存/格式限制仍要验证。纯文本或数据布局不需要不存在的 VM 指令 tier；涉及指令增删和控制流时按 [能力矩阵](parsing-evidence.md#能力不是全文件最低层级) 追加要求。

本地化通常需要变长，设计时应优先解决该主路径；但不能为宣称支持而越过未知引用。若只能原位修改，应清楚交付能力边界和阻断证据，不把每项任务都强制扩成完整重定位器。

每条修改保留源投影、行号、源对象、旧值/新值和目的字段。先构建不可变 ChangeSet，再求闭包与布局，不在遍历译文时立即向源文件写字节。

## 长度和容量

以下口径针对具体**未压缩字符串存储层**：

```text
payload_len = len(普通片段按 target_encoding 严格编码所得字节)
            + sum(保护 token 展开的原始字节数)
stored_len  = payload_len + 格式规定且尚未包含的终止符/前缀长度
```

长度前缀本身可能是变长整数；其宽度也随内容长度变化，应交给布局求解而不是固定加 4。终止符仅计一次。目标编码来自作业配置，不按字符数、source_encoding 或双行文件 UTF-8 字节数计算。

明确区分：

- `logical_length`：格式字段描述的字符数/字节数/码元数，单位由格式证据给出。
- `encoded_length`：目标文本编码后实际字节数。
- `slot_capacity`：该对象本次可合法写入的空间。
- `stored_length`：加终止符、头、对齐后该层占用。
- `compressed_size`：经过封装后实际大小，不能由明文增量直接推出。

容量的可信来源：显式分配长度；已证明的可写槽边界；在已证明区域内按已知编码/终止规则定位的原字符串长度；或已证明紧密排列且间隙归属于该槽时的相邻边界。原字符串长不等于分配容量，邻接偏移之差也不自动等于可用容量。

如果明确证明 padding 可复用，则可计入容量；若 padding 有校验、对齐或未知语义，不能擅自占用。短译文余下字节按已证明填充规则处理，或保留不被读取的原字节；不能普遍补零。容量未知返回阻断，不靠“试写后看是否崩溃”确认。

长度改变不是成功判据：新文本更长可能被原槽、padding 或块对齐吸收；压缩后总长可能不变或反向变化。成功看重新解析的目标内容、引用和依赖正确，不强迫输出文件长度改变。

## probe 与 run

```text
probe(ir, changes, options) → ProbeVerdict
run(ir, changes, approved_plan) → staged_output + RepackReport

ProbeVerdict:
  applicable, strategy_id, reason_code, blocking_refs,
  capability_scope, estimated_deltas, assumptions, plan_hash
```

`probe` 只读，无输出写入和隐式修改；不能把它实现成“试运行后删除结果”。估计压缩后大小等不确定值应标明估计，不伪装精确承诺。若必须运行压缩才能确定布局，可在已授权的临时规划阶段执行并记录，其结果属于计划数据而非已提交输出。

建议错误类别（实现只公布实际存在的代码）：

```text
NO_CHANGE / TIER_TOO_LOW / CAPABILITY_UNIMPLEMENTED / CAPACITY_UNKNOWN
LENGTH_OVERFLOW / POINTER_OVERFLOW / UNRESOLVED_JOIN_SITE / AMBIGUOUS_JOIN_KEY
ENCODING_UNREPRESENTABLE / PLACEHOLDER_BROKEN / SHARED_STORAGE_CONFLICT
UNREPLAYABLE_TRANSFORM / CHECKSUM_DEPENDENCY_UNKNOWN / LAYOUT_NONCONVERGENT
```

这些属于项目适配器契约，不表示随 skill 附带的静态检查器实现了所有策略。

`auto` 流程：

1. 对已实现策略做 probe，保存所有裁决和具体阻断对象。
2. 在可用策略中选满足请求的最小能力：identity → in_place → pointer-rewrite → full-layout。
3. 用已批准计划执行一次 run；复核源/参数/计划哈希，防止 probe 后输入变动。
4. run 失败停止该依赖分支，记录事件与 checkpoint，不自动试下一策略掩盖 probe 漏检。

用户显式指定策略可越过最小能力选择，但不能越过“不适用”。失败后可修正错误、生成新计划再重试，新的尝试拥有新 run ID，并保留原错误来源及退出码；不是隐藏失败的自动降级。

已授权完成整个回封任务时按请求推进，不需要每一个内部阶段重新询问。只有新范围、不可逆外部副作用、无法合理决定的歧义才需要用户决策。GUI 可提供可取消预览；CLI/批处理可通过显式确认参数或只写新目录完成同等契约。

## 按站点重定位

重定位单位为已证明的 `JoinSite(owner_object_id, field_id, target_object_id)`，不是“文件里值等于旧偏移的所有整数”。

```python
for site in plan.relocation_sites:
    new_site = plan.locate_field(site.owner_object_id, site.field_id)
    encoded = encode_reference(
        target=plan.locate_object(site.target_object_id),
        base=site.address_base,
        width=site.width,
        endianness=site.endianness,
    )
    write_exact(staged_output, new_site, encoded)
```

宽度、符号、相对基址、地址空间和范围全部显式。站点可移动，不能在 full-layout 后继续写旧 `site_offset`。两个层偏移相同不表示同一地址；引用目标内部偏移也要单独建模。

每次写入有归因：修改条目、引用槽、长度/计数、padding、校验或封装重编码。值恰好等于旧键的非站点必须保持不变，专门构造这种反例。`preserved_value_collisions` 是诊断量，零和非零都不能单独判断正确。

### 站点同构不是物理偏移相等

只做指针回填且站点不移动时，可比较原/新 `site_offset`。发生布局重排时用稳定 owner/field/target ID 的映射验证关系：旧站点和新站点一一对应，键类型/引用编码语义一致，目标依计划映射。声明了结构插删时比较计划中的新增/删除集合，不能无条件要求站点数永远相同。

共享目标的全部入站引用必须被纳入；若仅希望修改一个引用，需显式克隆目标并重定向该站点，否则属于冲突。对“全部引用已找到”的声明提供搜索域、解析范围、独立约束和已知未决项，不能把“已发现的全部”当成“真实的全部”。

## 叶到根传播

```text
TextEntry / StructuredEdit
  → 编码、token、终止符、长度字段
  → 共享存储与目标位置
  → 引用、标签、跳转/计数/表容量
  → payload 长度与对齐
  → 校验、压缩/加密
  → 父 VfsEntry 大小/偏移/FAT
  → 外层校验或签名
```

依赖图决定顺序，不机械执行固定七步：校验覆盖压缩前还是压缩后字节由格式给出；通常先子工件再父条目。闭包中未知的指针、跳转、校验、签名或变换阻断依赖它的策略。合法签名需要授权密钥时，无密钥不得假称已恢复有效签名。

先测算尺寸，再放置对象、求对齐、回填引用、重算依赖。对齐可用 `((offset + alignment - 1) // alignment) * alignment`，并验证 alignment 正数与格式约束。宽度变化或压缩造成循环依赖时设置确定的迭代/收敛准则和上限；不收敛明确失败，不能无限重算或偷偷采用最后一次结果。

未修改存储块可按原始哈希复用，避免重压缩引入不必要差异。未编辑子对象的语义和原始存储字节验证应分层：压缩块包含一个修改对象时整块压缩字节可能改变，这不表示其他对象内容可以变化。

## 提交与恢复

```text
固定源身份 → 计划 → 任务专属 staging → 写入 → flush/可用时 fsync
→ 重读并验证 → 同卷原子替换/改名到新输出路径 → 写提交记录
```

原件保持只读；目标默认是新目录。原子改名通常只保证单个文件、同一文件系统内的可见性，不自动保证整个批次的原子性，也不等于断电持久性。跨卷先在目标卷 staging 完整复制/验证；批次使用清单记录逐项状态，需全批原子时通过版本目录及一次指针/清单切换设计。

若各源无依赖，可继续其他源并报告部分成功；有跨源引用时按依赖闭包成组提交，不让一半更新进入可用输出。输出不能被第二次输入枚举重新吃入。

失败产物留在任务专属 `failed/` 并明确非交付，或按空间/敏感数据策略删除；保留足够日志、输入身份、计划和错误复现信息。取消仅清理本任务未提交临时输出，不删源、不删其他作业目录、不删已验证产物。

需要保存明文诊断层时与最终封装产物分开命名并记录层栈/哈希，不用加密结果覆盖同名明文。明文并非每个交付的强制产物：可能体积大或不适合持久保存，可在内存/临时目录验证后清理，报告实际保存范围。

回滚恢复的是明确的基线，不是推测逆向编辑。提供可重放恢复方式、基线哈希与目标限制；在独立副本执行恢复并比对哈希，不能拿未运行的脚本代替回滚验证。

## 结果验证

### 零编辑

- 实际经过该工具的解析—重建路径；输出逐字节等于源。
- 哈希辅助标识，逐字节相等是核心观测；源路径/哈希未变。
- 若实现 identity 快速路径直接复制，明确这只证明保留能力，不能充当已执行重编码器验证。

### 有编辑

- 用输出重新解析，验证覆盖、边界、计数、校验和适用策略的结构约束。
- 对每个 ChangeSet 对象核对新内容/字段；不以“搜索到某段译文”代替定位该对象。
- 未编辑对象内容保持，别名/共享及引用关系依计划成立；受影响站点完整对应。
- 每一差异字节都被允许修改区间的**并集完整覆盖**，仅“与合法范围相交”不够。
- 若布局整体位移，使用映射后的对象/区间验证；若压缩/加密层扩散，外层归因关联被重建块和内层证明，不能把全文件标为可改来绕过检查。

单个未压缩层的总长变化可解释为对象存储长度、表/前缀宽度、padding 等增量之和；该公式不套用外层压缩文件。哈希不同只证明字节变化，不能证明改对了；哈希相同也可能是语义未变的规范化请求，需报告无有效改动，不能宣称实际译文写入。

运行时加载/显示测试只有真正运行过才能标 pass。仅自身重新解析通过仍有共模盲区，报告 `runtime_validation=not_verified`，有独立读取器/目标程序时可增加交叉验证。门禁和证据格式见 [验证契约](validation.md)。
