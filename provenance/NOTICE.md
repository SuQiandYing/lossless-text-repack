# 来源、改编与许可证说明

本目录记录随 skill 提供的引擎资料、标准库实现、测试和辅助资源的来源、改动范围与许可证。游戏资源、私有密钥和运行结果不随包分发；`engines/` 与 `python/` 中的文件可以独立阅读和调用，不依赖外部仓库、GUI 或游戏进程。

## 许可分层

- 根目录原有规范、目录整理和既有辅助代码遵循根 [LICENSE](../LICENSE)。
- 移植的引擎模块按各文件的 SPDX 标识和本目录 `licenses/` 下的全文执行；GPL、MIT、BSD 和其他声明不能互相覆盖。
- 采用 GPL 代码的文件保留版权、许可证和修改说明；分发修改版时同时提供对应源码和许可证文本。
- `assets/uif/winmm.dll` 是单独记录的二进制资源，不因旁边的源码许可自动获得相同许可；使用前查看其 [资源说明](../assets/uif/README.md)。
- `sources.json`、各专题 JSON 和模块头给出提交、文件、符号、许可证及适用范围。没有明确授权的材料只作为研究资料，不自动升级为可分发实现。

## 目录与能力边界

`engines/` 的 95 个顶层页面和专项子页与 `catalog/engine-pages.json` 的文件/符号映射保持一致。`catalog/engines.json` 仍是能力状态注册表；登记、来源或测试数量都不能单独证明某个版本的游戏支持。每个 writer 必须由对应页面、合成正反例、零编辑往返、变长重解析和实际输入证据共同升级。

归档格式资料同时保留字段、偏移、编码、压缩和拒绝条件；Markdown 中的算法摘录用于解释和审计，不会执行 C#、Rust、EXE、DLL 或游戏脚本。Python 实现使用有界读取、显式参数和失败即拒绝，不能把宽松的历史工具行为当作当前支持承诺。

## 主要来源类型

- 归档与脚本格式参考：保留 MIT、GPL、BSD 等文件级通知，详细索引见 `provenance/archives.json`、`garbro-archive-notices.md` 和 `catalog/`。
- 公共编码与 JIS 字表：版本、哈希、改动和随包资源见 `jis-substitution.json` 与 `assets/uif/`。
- 引擎实现：每个模块头列出来源提交、采用的符号和本地化边界；对应测试只证明列出的合成形态。

验证报告写入本次结果目录，不收入来源记录。未执行宿主或游戏加载测试时，状态保持 `runtime: not_verified`。
